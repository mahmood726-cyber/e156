# Synthēsis Journal-Upgrade Program — v2 World-Class Index

**Goal.** Elevate each published Synthēsis paper to a world-class / PubMed-level
advanced version: ≥999 words, genuinely NEW self-contained analyses **verified by
a deterministic script**, exact denominators & definitions, reproduce-or-remove
discipline, verified PMIDs only (flag, never fabricate), careful framing, and an
evidence/confidence tier. Truth-first. Single writer. No live-journal publish
without separate approval — these are upgraded **drafts**.

**Layout.**
- `_manifest.md` — the 102 published papers with per-paper upgrade plans.
- `<id>-<slug>-advanced.md` — v1 drafts (prior session; ≥999 w, prose + tables,
  but no verification script; some placeholder values).
- `<id>-<slug>-advanced-v2.md` — **v2 world-class** upgrade (this program):
  every quantitative claim regenerated by a companion script; PMIDs PubMed-verified.
- `<id>-<slug>-verify.py` — the deterministic verification script for that paper
  (read-only; AACT snapshot for CT.gov papers, embedded published data for
  clinical MAs, seeded simulation for methods papers).

**Verification substrate.** AACT April-12-2026 full flat-file snapshot
(579,828 studies) at `$AACT_DIR` (discovered; fail-closed). Python 3.13 +
numpy/scipy. Every `-verify.py` prints the numbers pasted into its paper.

## Working notes / lessons (this program)

- **PMID verification is mandatory and catches real errors.** On paper 165, a
  blind "correction" pass introduced 3 wrong PMIDs (a docetaxel trial, a prune-
  belly case report, a lot-quality-sampling editorial). All were caught by
  fetching PubMed metadata and matching title+journal+pages before finalizing.
  Never assert a PMID without a metadata match. Prefer verifying the v1 PMIDs
  rather than rewriting them.
- **AACT parsing:** reassemble records by start signature (`^NCT\d{8}\|` for
  `studies`; `^\d+\|NCT\d{8}\|` for child tables) before splitting on `|` —
  text fields embed newlines. Assert the expected field width; report anomalies.
- **Reproduce-or-remove:** if a v1 claim doesn't reproduce, correct it in v2 and
  say so explicitly in an upgrade note; if data is unavailable, flag — don't
  fabricate.
